# 2026-09-01 — Cumulative agent-end capture must be non-semantic

- **Status:** Partial
- **Task/context:** Running the rc.67 paired project-instruction benchmark through the long `event-sourced-inventory` legacy cell.
- **Unexpected observation or failure:** The agent continued meaningful work beyond the old 2,400-second wall-clock cap, but the cell eventually became an infrastructure failure because one JSONL stdout line exceeded 1 MiB.
- **Evidence:** The cell ran for 8,168,925 ms, used 7,899,575 tokens and 348 tool calls, then hard-stopped with `capture overflow: stdout line exceeded 1048576 bytes`. Progress retained 313 semantic events and 168 mutations. The untrusted cell scratch recording was deleted by the existing failure-retention policy, so the exact overflowing event type cannot be proven retrospectively. Code inspection shows that JSON mode already projects cumulative `message_update` snapshots, while `agent_end.messages` still serializes the complete transcript as one non-metric line.
- **Approaches tried:**
  - **Attempt:** Introduce a generic lossless chunk-envelope protocol for every oversized JSON event.
    - **Outcome:** Did not work
    - **Why:** It would silently change the public JSON protocol, add base64 transport expansion and reconstruction state, and could create false liveness or metric counts from incomplete chunk headers.
  - **Attempt:** Raise or remove the 1 MiB per-line guard.
    - **Outcome:** Did not work
    - **Why:** It would weaken a useful resource boundary and allow relevant controller or metric events to consume unbounded parser memory.
  - **Attempt:** Stream exact raw bytes unchanged but discard only a newline-terminated oversized line with the exact canonical `agent_end.messages` prefix from the benchmark parser.
    - **Outcome:** Partial
    - **Why:** The cumulative event is not a metric or progress event and the raw recorder remains lossless, but prefix-only recognition was globally enabled and could misclassify a duplicate later `type`. It also counted a CR delimiter against the record limit when CRLF was split across stream chunks.
- **Root cause:** The benchmark applied a semantic per-record limit before it knew whether the record was a redundant cumulative lifecycle snapshot. `agent_end.messages` is the leading source-level cause, but rc.67 did not retain the failed raw line, so a successful live rerun remains necessary to confirm that no second oversized event type follows it.
- **Resolution:** Added a bounded incremental JSONL line capture that keeps at most the configured line limit plus one stream chunk in parser memory. The exception is enabled only for P task turns, and a streaming recognizer requires the exact canonical `type`, `messages`, and `willRetry` envelope before accepting the terminating LF or CRLF. Its raw ordinal advances once without semantic renewal; other producers, duplicate types, unknown or relevant records, and unterminated oversized records retain the original fail-closed overflow. A pending CR is held until the next byte so a split CRLF delimiter cannot create a false boundary overflow.
- **Verification:** A regression first reproduced the overflow. Focused and runner-wiring tests pass 14/14 and prove production-shaped nested messages at every split boundary for both retry values, same-chunk and split CRLF boundaries, byte-for-byte Brotli raw finalization, multiple skipped records with correct later ordinals, no semantic-liveness renewal, P-only enablement, and fail-closed behavior for wrong producers, duplicate types, oversized `message_end`, and unterminated `agent_end`. The adjacent capture/evidence family passes 31/31, the benchmark suite passes 387/387, `npm run check` and `./test.sh` exit zero, and `./reinstall.sh` installs and verifies `p` 0.4.224 without restarting the unchanged indexer. Live rc.68 evidence remains pending.
- **Prevention/follow-up:** Preserve raw failed prefixes or a sanitized event-type diagnostic in future infrastructure failures when that can be done without retaining untrusted payloads. Do not add another safe-drop type without an exact reproduction and proof that it is non-semantic and already represented elsewhere.
- **Reusable learning:** Apply payload limits after distinguishing redundant cumulative lifecycle snapshots from evidence-bearing events; skip only an exact audited non-semantic form, never generic oversized output.
