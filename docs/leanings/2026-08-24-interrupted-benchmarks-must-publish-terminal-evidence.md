# 2026-08-24 — Interrupted benchmarks must publish terminal evidence

- **Status:** Partial
- **Task/context:** Running the randomized legacy-versus-compiled task 3 benchmark for the `5.0.1-rc.1` and `5.0.1-rc.2` project-instruction candidates.
- **Unexpected observation or failure:** The first legacy cell entered repeated requirement-definition retries. Stopping `rc.1` with SIGINT bypassed benchmark finalizers, left a private fixture root behind, and preserved an initial result sentinel whose correctness gate still appeared to pass while the run was incomplete. The first cooperative `rc.2` interruption correctly failed the gate and removed owned resources, but published terminal evidence before global finalization, so it could not attest cleanup; its incomplete semantic recording also exposed no lower bound for the observed definition attempts. Liveness initially counted requirement definition as mutation and retained a stale phase.
- **Evidence:** The stopped `rc.1` cell ran for about 1,850 seconds, attempted six rejected definition batches, produced no accepted sample, and left `completed: false` with `summary: null`. Its closed benchmark log and progress evidence were recovered and stored with Brotli quality 6; the leaked private root had no live owner and was moved to Trash. The interrupted `rc.2` cell produced `runStatus: "interrupted"`, a false gate, no sample, compressed mode-`0600` progress evidence, and no leaked process or private root, but its terminal document omitted cleanup attestation even though five definition attempts were observed before the partial recording closed.
- **Approaches tried:**
  - **Attempt:** Rely on abrupt process termination and the initial positive gate sentinel.
    - **Outcome:** Did not work
    - **Why:** Signal termination skipped cooperative child shutdown and final evidence publication, while a positive sentinel described an unearned future state.
  - **Attempt:** Propagate one abort signal through the outer harness, cell, runner, and agent turn; terminate children with bounded SIGTERM-to-SIGKILL escalation; await child close; finalize sanitized progress; and publish an explicit lifecycle state.
    - **Outcome:** Partial in the first live run, then worked after focused correction
    - **Why:** Cooperative shutdown removed owned resources, but the first implementation published before global finalization. Moving terminal publication to the global owner now makes cleanup status part of the same terminal transaction, while correctness remains false until all samples and cleanup pass.
  - **Attempt:** Treat every `record_requirement_audit` invocation as a potentially mutating action.
    - **Outcome:** Did not work
    - **Why:** Requirement definition is planning and distorted the first-mutation timestamp and semantic phase used for live diagnosis.
  - **Attempt:** Run the full unit suite through a compression wrapper whose command lifetime is capped at 120 seconds.
    - **Outcome:** Did not work
    - **Why:** The wrapper terminated the healthy long-running suite before `test.sh` could execute its auth-restore trap. The credential backup was restored only after verifying that the live path was absent and the mode-`0600` backup was present; the suite was then rerun through a quiet file-backed wrapper with compression disabled only for that long command, and its closed log was stored with Brotli Q6.
- **Root cause:** Benchmark process signals were not represented in the internal control flow, the persisted gate modeled optimistic intent instead of achieved state, terminal evidence was initially published before global cleanup, and liveness inferred phase only from tool starts without a separate requirement-definition lifecycle or an explicit exact-versus-observed count distinction.
- **Resolution:** Introduce explicit `running`, `completed`, `failed`, and `interrupted` run states; keep the gate false until complete; propagate cooperative cancellation and wait for child close before cleanup; publish terminal results only after global finalization with sanitized cleanup status; publish private progress atomically as Brotli Q6; track requirement-definition start/end as planning rather than mutation; and keep the exact attempt count `null` when semantic evidence is incomplete while reporting the observed lower bound as `at least N`.

The full script suite passes 292/292; focused interruption and liveness regressions pass 73/73, with an independent adversarial re-review passing 56/56. Resistant-grandchild, nested detached-agent, real SIGINT/SIGTERM, passing-cell race, secondary-error, rejected-termination, publication-failure, active-progress-permission, and cleanup-failure regressions are included. `npm run check` passes for 592 checked files and the 1,995-file structure gate. The complete non-e2e unit gate passes: agent 383/383, AI 593/593 with 747 skipped, code-index 381/381 plus Python 81/81, coding-agent 2,779/2,779 with 49 skipped, script 292/292, and release audit 61/61. Reinstall passes. An isolated installed smoke proves compiled-size and authoritative pre-mutation gating; its later model overreach remains explicitly classified as a task-correctness failure. A fresh `5.0.1-rc.3` paired task 3 run remains required after the final correction.
- **Prevention/follow-up:** Keep process-level SIGINT/SIGTERM integration coverage, assert that no owned private root remains, reject any incomplete artifact with a passing gate, and inspect live progress at least once per minute during benchmark cells. For commands expected to exceed the compression runtime's command-lifetime cap, redirect all output inside a file-backed wrapper, bypass compression only for that command, verify cleanup traps and sensitive-file restoration explicitly, then Brotli-Q6-compress the closed log.
- **Reusable learning:** Long-running benchmarks must treat interruption as a first-class terminal transaction: cancel cooperatively, await descendants, clean private state, and publish evidence that describes only achieved correctness.
