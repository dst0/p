# 2026-08-25 — Core AI artifact caches require runtime loadability verification

- **Status:** Resolved
- **Task/context:** Installing and smoke-verifying the macOS Apple Silicon Core AI embedding runtime for the background code indexing daemon.
- **Unexpected observation or failure:** Structurally valid cached Core AI artifacts failed during `AppleCoreAIWorker.initialize()` with `Foundation._GenericObjCError` and native MPSGraph `cacheIdentifier` load errors during `AIModel.load_function`. Reinstalling reused the invalid cached artifact without repairing it because the installer only checked for file and directory presence.
- **Evidence:** Installer log recorded worker initialization crash while `apple_coreai_artifact.py` skipped export because `artifact.json`, `model.aimodel`, `embedding-table.npy`, and `tokenizer` were present. An isolated fresh export produced a different `main.mlirb` hash that successfully loaded and placed fully on the Apple Neural Engine (`mps.fullyPlacedOnANE` and `mps.noGPUActivity`).
- **Approaches tried:**
  - **Attempt:** Purge global Apple or OS MLIR/MPS caches broadly across the system.
    - **Outcome:** Did not work
    - **Why:** Broad cache deletion risks side effects on unrelated system frameworks and models, and does not provide deterministic self-healing when an isolated artifact becomes internally inconsistent.
  - **Attempt:** Rely solely on filesystem marker checks (`artifact.json` and directory structure) to decide whether to reuse or export.
    - **Outcome:** Did not work
    - **Why:** Structural checks cannot detect native MLIR/MPSGraph deserialization errors or runtime kernel incompatibility within an otherwise intact artifact directory.
  - **Attempt:** Build mutable in-place generations and copy backup directories to recover on failure.
    - **Outcome:** Did not work
    - **Why:** In-place mutations and copy backups introduce race conditions during concurrent installation, risk deleting active generations on promotion ambiguity, and perform unnecessary disk I/O.
  - **Attempt:** Probing the current pointer first, exporting to immutable unique candidate generation directories (`${artifactVersion}-${UUID}`), directly probing candidate loadability and ANE residency, and atomically promoting `current.json`.
    - **Outcome:** Worked
    - **Why:** Every candidate is immutable and isolated, concurrent builders require no lock, the builder cleans its private temporary on export failure without touching candidate destinations or existing assets, failed candidate probes clean only their own unique generation directory, and atomic pointer promotion guarantees the active pointer always references a fully validated generation. Old generations are deliberately retained and conservative garbage collection is a separate future design.
- **Root cause:** Core AI compilation artifacts can become unexecutable across native runtime or system changes even when all constituent files remain present on disk. The artifact preparation logic only validated filesystem presence, preventing self-healing during reinstall.
- **Resolution:** Added a one-shot `--probe` mode to `apple_coreai_worker.py` supporting both `--artifact-root` and direct `--artifact-directory`. `apple_coreai_artifact.py` builds immutable unique candidate generations named with canonical version plus UUID into private `.building` temporaries with atomic destination placement. Structured bounded process execution in `scripts/bounded-process-command.js` handles async spawn, separate bounded stdout/stderr streams, detached POSIX process-group cleanup on timeout or overflow, and sanitized diagnostics. `ensureAppleCoreAiArtifact` in `scripts/install-apple-coreai.js` probes the current pointer first, builds exactly one candidate on probe failure or missing pointer, probes the candidate directory directly, and atomically promotes `current.json` via unique mode-`0600` fsynced temp files. Existing generations are never renamed, overwritten, or deleted, old generations are deliberately retained, failed candidate probes clean only their own unique directory, and failed builds leave candidate cleanup to the Python builder's private temporary directory.
- **Verification:** Ran unit regressions in `scripts/install-apple-coreai.test.js`, `scripts/install-apple-coreai-artifact-recovery.test.js`, and `scripts/bounded-process-command.test.js` covering healthy cache reuse, missing/corrupt pointer recovery, event ordering, export failure cleanup, candidate probe failure isolation, pointer promotion failure candidate retention, concurrent interleaved installer safety, descendant socket cleanup on timeout, buffer overflow termination, production health contract, and diagnostic sanitization. Ran Python unit tests in `packages/code-index/test/test_apple_npu_backends.py` and `packages/code-index/test/test_apple_coreai_artifact_generations.py` validating probe execution with `AsyncMock` initialization, candidate name/UUID validation, destination collision rejection, pointer schema resolution, traversal/symlink rejection, and metadata verification. Ran `npm run test:scripts`, `npm run check`, and `git diff --check`.
- **Prevention/follow-up:** Always execute a lightweight real initialization probe before declaring a native accelerator cache valid; capture stdout and stderr separately so diagnostics do not corrupt protocol payloads; and pair cache validation with immutable unique candidate generation and atomic pointer promotion rather than destructive in-place replacements. Old generations are deliberately retained; any conservative garbage collection remains a separate future design.
- **Reusable learning:** Compiled accelerator model caches must be verified via real load/residency probes rather than structural file presence checks, with self-healing structured as immutable candidate generation and atomic pointer promotion that deliberately retains historical generations and never modifies working assets in place.
