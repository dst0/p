# 2026-08-24 — Benchmark evidence must mirror runtime markers and prompt projection authority

- **Status:** Partial
- **Task/context:** Certifying the installed compiled-instruction runtime before assigning the first immutable `5.0.1-rc.N` paired-benchmark candidate.
- **Unexpected observation or failure:** The installed compiled startup probe reported that no compiled marker was present even though the cache held a successful compact artifact. The benchmark also assumed one manifest source, treated only the canonical artifact prompt as valid, retained untrusted child evidence objects after checking their required fields, and initially let child-writable files authorize startup proof and result evidence.
- **Evidence:** The live v14 artifact contained four source records, a 344-byte always-on body, a 1,198-byte canonical prompt, and a 1,964-byte worst-case injected result. Its marker included `agents_sha256`, `input_sha256`, and `mode`, but the old adjacency-sensitive expression expected `mode` immediately after the agents hash. Production had also correctly removed exact reader/fallback guidance for the available tool set, so the injected prompt hash differed from the canonical manifest hash.
- **Approaches tried:**
  - **Attempt:** Relax only the failed marker expression and accept the manifest prompt hash directly.
    - **Outcome:** Did not work
    - **Why:** It would preserve duplicate grammar, miss marker/source identity, and authorize a canonical prompt that production never injects.
  - **Attempt:** Use one strict shared marker parser, identify exactly one canonical workspace source within a multi-source manifest, enumerate production-exact tool-conditioned prompt projections before task work, bind that set into the immutable seed receipt, and project every child/public evidence object into an exact schema.
    - **Outcome:** Worked
    - **Why:** Runtime and benchmark now share one marker contract, unknown or malformed nested data either disappears or fails the correctness gate, and authority is derived before untrusted task work.
  - **Attempt:** Publish the proof to a child-workspace file, then replace it with one cell receipt carried through child-written `results.json`.
    - **Outcome:** Did not work
    - **Why:** A same-UID model descendant could discover paths or ancestor arguments, rewrite or pre-link evidence, omit matching child-derived turns, replay a proof within the same cell, or race publication and commitment.
  - **Attempt:** Use prompt-bound per-turn IPC receipts plus a distinct parent-owned outer IPC commitment over the exact pre-publication result bytes.
    - **Outcome:** Worked
    - **Why:** Neither P tools nor descendants inherit the authority channel; exact launched-turn count and prompt bytes are parent-known; delivery hard-stops before provider work; and the outer process independently validates bounded no-follow result bytes.
- **Root cause:** The benchmark independently approximated evolving runtime syntax and treated validation of child-owned data as if it also sanitized and established authority. File paths and exposed receipt hashes identify evidence but do not make its publisher trustworthy.
- **Resolution:** Centralize strict marker parsing; bind agents hash, input hash, artifact mode, exact workspace source path/hash, cache closure, and all authorized prompt projections; issue distinct prompt-bound receipts for every launched turn; require one matching proof and user event per turn; transmit final authority through a non-inherited outer IPC channel; commit in-memory result bytes before exclusive publication; and exact-pick all retained public schemas.
- **Verification:** The script suite passes 267/267 and the complete non-e2e unit suite passes in 274,096 ms; authority-focused regressions cover dropped IPC sends, caught extension errors, replay, duplicate-frame bounds, descendant rewrite races, symlink publication, missing authority, exact raw-byte commitments, invalid UTF-8, and composed outer/turn/descendant IPC containment. Independent review reports no remaining P0 or P1. Reinstall and rebuilt same-provider compiled/legacy smoke remain required before this learning is fully resolved.
- **Prevention/follow-up:** Regenerate installed compiled and legacy proof evidence after reinstall, never reuse the stale pre-parser proof, keep exact-set parity tests wherever the immutable JavaScript benchmark snapshot duplicates a production constant, and never let a child-writable artifact certify its own authority.
- **Reusable learning:** Benchmark evidence is a security boundary: mirror runtime grammar exactly, derive authority before untrusted work, bind every launched turn to parent-known input, and commit exact bytes through a channel descendants cannot inherit.
