# 2026-09-23 — Compiler fallback must degrade to legacy delivery, not block work

- **Status:** Resolved
- **Task/context:** Owner report on 2026-09-21: "Where did read-only come from? How do I make the agent change files?" A workspace whose `.pdev/instructions` artifact was in `fallback` mode (configured compiler model endpoint down) could not edit files in the default `compiled` project-instruction delivery.
- **Unexpected observation or failure:** Every potentially mutating tool call was rejected with `Compiled project instructions are unavailable. Reload with project instruction mode legacy before mutating work.`, and every turn injected `<project_rule_routes>Compiled project instructions are unavailable. Do not mutate; restart in legacy mode.</project_rule_routes>`. The system prompt carried only the fallback catalog stub, not the AGENTS.md content.
- **Evidence:** Harness regression `packages/coding-agent/test/suite/regressions/compiled-fallback-legacy-delivery.test.ts` run against the unmodified `origin/main` production code (`a49636230`): the fallback `write` tool result was `isError: true` with the message above and the target file was never created; the compiled-success gate test passed on both revisions. An isolated TUI run with a dead compiler endpoint and a stub task model showed the warning line, a successful `write`, and task-model requests containing `<project_context>` plus `<project_rules>` and no "Do not mutate".
- **Approaches tried:**
  - **Attempt:** Previous fix (#124, see [2026-09-21 fallback read passthrough](2026-09-21-fallback-guards-need-effect-aware-read-passthrough.md)) allowed effect-declared reads and read-only shell inspection while keeping mutations blocked in fallback.
    - **Outcome:** Partial
    - **Why:** Inspection worked, but the agent still could not change files; the session stayed effectively read-only until the user discovered `--project-instructions legacy`.
  - **Attempt:** Retry compilation inline before tool calls or in the background while degraded.
    - **Outcome:** Rejected for this change
    - **Why:** Inline retries stall tool calls for up to the provider timeout (default `httpIdleTimeoutMs` is 300 s per attempt), and every compiled/legacy flip rewrites the system prompt and invalidates local-model prefix caches. Background compilation is a follow-up option that needs single-flight refreshes and turn-pinned delivery.
  - **Attempt:** Resolve delivery from the live artifact everywhere, including model-visible history filtering.
    - **Outcome:** Did not work
    - **Why:** Adversarial review showed a mid-run fallback stripped the run's `<project_rule_routes>` history while its system prompt stayed compiled, and a recovered compiled turn replayed a stale pre-fallback batch (`Project instructions changed since the persisted routed turn`).
  - **Attempt:** Gate and prompts follow the live artifact, model-visible history follows the delivery the run's prompt was built with, transitions apply at the next user turn with a `delivery-change` supersession marker, and entry into fallback emits one `project_instructions_fallback` notice.
    - **Outcome:** Worked
    - **Why:** Legacy delivery is the documented baseline and already carries the authoritative source text; a fallback artifact can never satisfy compiled routes, so gating on it only strands work.
- **Root cause:** `createProjectRuleTurnContext` (`prompt-context.ts`) turned a `fallback` artifact into a failure gate plus a "Do not mutate" route block, `getProjectRuleBlockReason` (`tool-hooks.ts`) returned the fallback block reason for every potentially mutating tool, and the system-prompt builder only injected context files for the configured `legacy` mode, so fallback sessions had neither compiled rules nor legacy context.
- **Resolution:** `project-instruction-fallback-delivery.ts` resolves `compiled` + `fallback` to `legacy` delivery; `syncProjectInstructionFallbackDelivery` applies transitions at turn start. The successful compiled path, including `read_rules` batches and route-change blocks, is unchanged.
- **Verification:** The harness regression covers steady-state fallback, the unchanged compiled gate, reload recovery, notice lifecycle, mid-run fallback with same-identity model-switch recovery, and a compiler-less SDK session; a scratch mutation probe of 12 targeted mutants was fully killed. All 86 project-instruction-related test files pass and `npm run check` passes.
- **Prevention/follow-up:** A missing optimization layer (compiled routing) must fall back to the documented baseline (legacy injection) with a user-facing notice, never to a read-only gate. Follow-ups: compile in the background while legacy serves the first turn, let an explicit `/reload` bypass the five-minute compiler failure backoff, and review the remaining fail-closed resume paths in `restoreProjectRuleGateFromHistory`.
- **Reusable learning:** When an optional optimization layer fails, degrade to the documented baseline with a notice; change model-visible context only at user-turn boundaries, and supersede state bound to the replaced artifact when switching back.
