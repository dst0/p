# 2026-09-02 — Live proof discovery must use canonical source paths

- **Status:** Partial
- **Task/context:** Validate the evidence-mode terminal-byte proof protocol with a live compiled-instructions canary before starting the 5.0.1 paired benchmark.
- **Unexpected observation or failure:** The canary read the prompt-referenced `FORMAT.md`, implemented and tested the requested final-LF rejection, but every persisted verification state still had zero critical-proof obligations and no `P_PROOF_V1` frame was emitted. Separate high-risk selector feedback then looped because it did not explain which semantic parts the selected test name omitted. Follow-up review found that a case-only path alias still missed the prompt candidate, rejected symlink, hardlink, or otherwise uninspectable authoritative sources were silently converted into the same empty-obligation state, and the model could bypass discovery entirely by never reading the referenced source. A literal `P_PROOF_V1` mention also overcorrected into false proof debt for documentation tasks, while source deauthorization disappeared after an unrelated prompt.
- **Evidence:** The closed Brotli Q6 canary log is `/tmp/p-rc71-evidence-proof.jsonl.br`. Its read descriptor used an absolute in-workspace path, its source said a non-empty export must “end with exactly one LF byte,” and the log contains no `P_PROOF_V1` frame. Focused reproductions showed the absolute path and phrase recognizer each independently suppressed discovery. Selector checks showed that a whole test file, a dedicated `calculator.truncation.test.ts`, and `truncation.*throws.*partial` were correctly insufficient, but all received the same generic rejection.
- **Approaches tried:**
  - **Attempt:** Continue the canary after repeated generic focused-test rejection.
    - **Outcome:** Did not work
    - **Why:** The model created and reran narrower tests without knowing that its selector omitted preservation behavior and a second criterion-specific term.
  - **Attempt:** Loosen focused-evidence relevance or infer relevance from runner output.
    - **Outcome:** Rejected
    - **Why:** A broad or unrelated test file could masquerade as focused evidence; runner-output parsing is ecosystem-specific and test code can print arbitrary text.
  - **Attempt:** Keep the guard and prescribe one safe complete case name derived from the frozen criterion.
    - **Outcome:** Worked in focused tests
    - **Why:** The exact next repair becomes framework-neutral and bounded without exposing the rejected command or weakening semantic matching.
  - **Attempt:** Normalize the raw read path only as a relative requirement-source path.
    - **Outcome:** Did not work for live runs
    - **Why:** Models commonly pass absolute paths to `read`, and the safe relative-path normalizer intentionally rejects them.
  - **Attempt:** Compare canonical `realpath()` strings for case-only aliases.
    - **Outcome:** Did not work
    - **Why:** On the observed macOS filesystem, both aliases resolved to the same file but `realpath()` preserved the caller's casing, so the strings still differed.
- **Root cause:** Proof discovery assumed a model read would occur and that its tool argument used the prompt’s relative spelling, while recognizing only narrow newline phrases. Live reads commonly use absolute in-workspace paths, case-insensitive filesystems can expose multiple spellings for one inode, and natural specifications may insert cardinality words and `byte` between “end with” and `LF`. Inspection errors were treated like irrelevant reads instead of durable safety debt. Deauthorization looked only at the last prompt, and the explicit-demand backstop matched a protocol token without understanding whether it was requested behavior. Because readiness enforced only discovered obligations, omission and representation differences could silently bypass proof.
- **Resolution:** Prompt capture now deterministically inspects every active prompt-authoritative candidate and derives bounded critical obligations before checklist recording or mutation, so source reads are refresh observations rather than the sole discovery trigger. Case-only read aliases match the prompt candidate by device and inode after rejecting symlinks and hardlinks. Unsafe or uninspectable authoritative sources create bounded persisted discovery failures that survive session restoration and block checklist recording, mutation, and readiness until safe replacement plus reread or durable explicit user deauthorization. Unrelated prompts preserve deauthorization; explicit reauthorization activates and rescans the source. Terminal-newline recognition accepts bounded “exactly one LF byte” variants. Only semantic witness demands activate the no-obligation backstop; incidental and documentation mentions do not. Semantically incomplete focused selectors receive one safe complete case-name repair; broad evidence retains the generic rejection.
- **Verification:** Failing-first regressions reproduced no-read and absolute/case-alias discovery misses, symlink and hardlink fail-open behavior, non-durable deauthorization, incidental-token false positives, the live LF-byte phrase, the zero-obligation readiness false positive, and the selector loop. Focused tests cover prompt-time discovery, wrong/outside read non-substitution, persisted restoration and mutation blocking, safe source replacement and reread through the restored controller, durable deauthorization plus explicit reauthorization, docs and implementation token mentions, semantic witness requests, three incomplete selector shapes, exact-selector recovery, and generic-suite rejection. A fresh installed live canary remains pending.
- **Prevention/follow-up:** Every proof canary must assert obligation creation immediately after source discovery, not only inspect the final readiness result. Compare filesystem objects by trusted identity metadata after path-safety checks, never by normalized or `realpath()` strings alone. Keep an independent semantic check of the canary implementation because a relevant test name is evidence routing, not proof that the test assertion is complete. Add natural-language fixtures from actual live prompts whenever a recognizer is expanded.
- **Reusable learning:** Fail-closed validation is incomplete when safety depends on the model choosing to perform a discovery read. Derive bounded obligations deterministically from authoritative inputs before mutation, treat later tool observations as refreshes, bind aliases by safe file identity, persist inspection failures, preserve negative authorization across unrelated prompts, and distinguish semantic demands from incidental protocol-token mentions.
