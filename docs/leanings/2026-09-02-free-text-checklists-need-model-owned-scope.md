# 2026-09-02 — Free-text checklists need model-owned scope

- **Status:** Partial
- **Task/context:** Restore evidence-mode liveness for a large free-text specification while keeping one concise model-generated completion checklist and universal evidence semantics for code and non-code work.
- **Unexpected observation or failure:** The rc.75 task-3 run completed 13 mutations before checklist recording, then alternated between a qualifier-complete checklist over the 1,200-character ceiling and a concise checklist rejected for missing source qualifiers.
- **Evidence:** The 3,288-byte inventory README produced 17 lexical qualifier frames even though a 1,199-character seven-item behavioral checklist represented the task. Exhaustive and selection-scoped parsers both produced false positives and false negatives across actions, source deletion, approval, scheduling, privacy, and multilingual text. Separately, safe external-effect criteria demanded impossible shell tests, while only the latest external receipt remained eligible.
- **Approaches tried:**
  - **Attempt:** Raise the checklist character ceiling.
    - **Outcome:** Did not work
    - **Why:** A larger source recreates the same contradiction, and lexical qualifier coverage still neither proves behavioral completeness nor remains universal.
  - **Attempt:** Require every qualifier frame from every authoritative-source clause.
    - **Outcome:** Did not work
    - **Why:** This reconstructed the exhaustive clause matrix the free-text evidence mode intentionally avoids and created a length-versus-coverage repair loop.
  - **Attempt:** Enforce qualifiers only for source subject frames selected by the checklist.
    - **Outcome:** Did not work
    - **Why:** Generic noun overlap still borrowed qualifiers across actions, subject-changing source drift bypassed or deadlocked renewal, and English lexical rules could not cover universal free text.
  - **Attempt:** Keep checklist scope model-owned and reserve hard gates for structural proofs and effect-bound receipts.
    - **Outcome:** Partial
    - **Why:** Focused and domain tests pass; live AI-unit and paired benchmark evidence remain pending.
- **Root cause:** Source completeness, semantic selection, and proof policy were conflated. Deterministic lexical code cannot prove that arbitrary free text is exhaustively represented, and code-test evidence cannot stand in for connector effects, approvals, document inspection, or operational state.
- **Resolution:** Keep one model-generated behavioral checklist with 12-item, 300-character item, and 1,200-character stored-body limits. Accept at most 24 input items so process-only evidence can be removed before the stored limits without the provider schema rejecting the call first. Do not reparse authoritative free text as a blocking matrix. Retain bounded exact-final-byte proof. An ordinary read never promotes a referenced output into an authoritative source; when language-neutral prompt recognition is insufficient, the model selects up to three referenced paths in the checklist call and the controller accepts only existing, safe Git-tracked files. Each selected source retains its prompt epoch, including sources with no recognized critical boundary, so only a later direct instruction can de-authorize it and later re-selection can authorize it again. External receipts persist an immutable receipt ID and exact tool identity, remain visible and eligible after later effects, and map once only to a bounded successful-tool criterion. A semantic remote outcome needs that receipt plus a later declared readback whose native tool result explicitly confirms the original write call and exact checklist criterion. The controller validates the relationship and stores only the receipt identity and criterion hash; shell/file, negative, wrong-resource, unconfirmed, and superseded readbacks cannot substitute.
- **Verification:** Failing-first large free-text, process-item budget, multilingual nudge, source authority/lifecycle, receipt semantic binding, receipt/readback restoration and redaction, status recovery, finish-time requested-evidence, and multi-effect regressions; 160 task-verification/requirement test files with 1,327 tests pass and `npm run check` passes. Full repository, reinstall, live AI-unit, and paired benchmark verification are pending.
- **Prevention/follow-up:** Preserve a real large-spec checklist fixture, source prompt-epoch lifecycle coverage, and cross-domain external-effect proof tests. Never expand a resource ceiling to accommodate an automatically reconstructed free-text matrix, and never infer remote semantic success from tool-call co-occurrence. Require a cheap live AI-unit to reach checklist acceptance without alternating diagnostics before starting a full paired benchmark.
- **Reusable learning:** Let the model own free-text completion scope; use deterministic hard gates only where structure or immutable effect identity makes the invariant provable, and never let a successful tool receipt imply semantics it did not record.
