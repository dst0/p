# 2026-09-08 — Image budget accounting needs adapter capabilities

- **Status:** Corrected
- **Correction (2026-09-08):** An earlier draft assumed `is_byok` was part of inline chat `usage`. The official OpenRouter contract documents `is_byok`, `total_cost`, and `upstream_inference_cost` on authenticated `GET /api/v1/generation?id=...`; the implementation and regressions now use that endpoint and fail closed when its metadata is unavailable.
- **Task/context:** Validate token and estimated-USD run budgets across image-generation calls.
- **Unexpected observation or failure:** A valid image call with an exact provider-reported cost was rejected when its input token rate was zero, while partial OpenRouter token fields were accepted as complete by filling absent counts with zero. Public adapter registration also accepted malformed or mutable accounting declarations. Adversarial follow-up found that model-rate settlement trusted a plausible response total even when its token counts were invalid, unsupported adapters could still mark USD known, the mutable registry record could replace a frozen declaration, text settlement discarded provider-computed priority and extended-cache prices, missing rate properties passed `Object.values` validation, inconsistent token totals were accepted, an all-zero error sentinel was treated as a known free text call, and OpenRouter account/upstream costs were combined with an ambiguous maximum without checking BYOK metadata.
- **Evidence:** Failing-first regressions reproduced each failure: USD admission failed before a cost-only fake OpenRouter dispatch; prompt-only, negative, and inconsistent token reports produced fabricated or ready `Usage`; a token-limited OpenRouter call dispatched despite its optional token telemetry; an unknown USD capability was admitted as model-rate accounting; mutating a declaration after admission changed settlement; invalid counts with a plausible total cleared USD uncertainty; priority and one-hour cache-write totals were reduced to static rates; missing named rate fields dispatched; non-BYOK upstream cost replaced the account charge; and BYOK account plus upstream spend was undercounted.
- **Approaches tried:**
  - **Attempt:** Treat zero model rates as evidence that image generation is free.
    - **Outcome:** Did not work
    - **Why:** Image providers can bill per image, megapixel, request, or token; zero token rates do not bound the charge.
  - **Attempt:** Derive every image charge from the number of returned images and one static output rate.
    - **Outcome:** Did not work
    - **Why:** Quality, dimensions, provider routing, and pricing units can change the actual charge.
  - **Attempt:** Let each image adapter declare whether it reports tokens and exact USD, then persist those dimensions independently.
    - **Outcome:** Worked after hardening
    - **Why:** Runtime validation plus immutable snapshots reject malformed or changing declarations; admission rejects unsupported policies before side effects, while exact reported cost remains usable without fabricated token counts.
  - **Attempt:** Read the OpenRouter BYOK discriminator from inline chat `usage`.
    - **Outcome:** Did not work
    - **Why:** The documented inline usage schema does not contain `is_byok`; authoritative accounting metadata is exposed by the authenticated generation lookup.
- **Root cause:** The ledger applied a text-token pricing contract to all model kinds and returned before USD settlement whenever token usage was absent. The first capability design also treated TypeScript unions as runtime validation, treated any optional token field as a complete report, validated only enumerable rate values rather than required keys, and conflated two OpenRouter cost dimensions without the `is_byok` discriminator.
- **Resolution:** Added validated adapter accounting capabilities on immutable registry-owned provider records; require all four named rate fields and exact token-component totals; retain internally consistent provider-computed text totals when they exceed static rates; reject the zero-token/all-zero-cost text error sentinel while preserving independently reported image zero charges; keep image estimates out of the exact provider-total channel; use the returned OpenRouter generation ID for one bounded authenticated metadata GET; use `total_cost` for non-BYOK and `total_cost` plus `upstream_inference_cost` for BYOK; preserve the image but fail closed for later USD dispatch when the ID or metadata is unavailable; reject unsupported token/USD image policies before dispatch; and keep `Usage.cost.total` equal to its component sum while storing exact aggregates only in `reportedUsd`.
- **Verification:** Failing-first AI registry, OpenRouter parsing, ledger, and session-scope regressions cover POST-then-GET ordering, encoded generation IDs, authentication/header/signal forwarding, contradictory inline billing fields, malformed generation metadata, chunked oversized response cancellation, metadata lookup failure, cost-only, complete, partial, negative, inconsistent, malformed, mutated, unsupported, request-limited, no-repeat uncertain admission, zero-token text sentinels, independently reported image zero cost, OpenAI priority, Anthropic one-hour cache writes, missing rate fields, BYOK/non-BYOK account semantics, separate cache reads/writes, and conservative-pricing cases.
- **Prevention/follow-up:** New image adapters must declare only accounting fields guaranteed before dispatch; validate capability objects at runtime and snapshot them before asynchronous work. Add token support only when the adapter guarantees complete telemetry, and direct OpenAI USD support only with response parsing and bounded variant pricing.
- **Reusable learning:** Model kind, adapter response guarantees, runtime declaration validation, telemetry completeness, and billing discriminators are part of budget accounting; never infer zero from an absent token or cost component, trust an aggregate that conflicts with its breakdown, or combine account and upstream charges without knowing whether the request was BYOK.
