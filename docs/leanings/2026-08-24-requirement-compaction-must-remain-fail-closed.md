# 2026-08-24 — Requirement compaction must remain fail-closed

- **Status:** Partial
- **Task/context:** Reducing repeated requirement-definition prompt cost after the task 3 agent looped on a 55-clause referenced specification.
- **Unexpected observation or failure:** An initially green optimization auto-classified all prose missed by a narrow normative heuristic and split camel-case identifiers before ordinary token-overlap checks. This could silently discard an imperative such as `Retry failed requests three times.` or accept `deleteBatch` as support for an `executeBatch` requirement. During the first `5.0.1-rc.2` task 3 cell, an atomic `src/index.ts`/`ConcurrencyError` export was also rejected because the period in the file extension was counted as a sentence boundary; plural `SKUs` was split as an identifier; and `npm test` could not map atomically from a clause that also named `npm run typecheck`. After those fixes, `5.0.1-rc.3` still oscillated for eight definition attempts around one atomic batch clause instead of converging.
- **Evidence:** Five fail-open regressions failed before the original corrections: ambiguous informational prose, a partial compound collision, a shared secondary identifier, a snake-case collision, and an over-strict multi-identifier atomic split. The live `rc.2` requirement-definition diagnostics then decreased only `18 → 18 → 13 → 9 → 8` across five complete batches before interruption. Focused regressions reproduced four additional deterministic failures: three plural-acronym mappings and the exact `npm test`/`npm run typecheck` split. The capacity regression also proved that the former 64-item ceiling rejected a valid bounded 96-item definition. A dense catalog measurement showed that changing representation alone does not prove lower prompt cost unless its bytes are bounded against the prior representation. In `rc.3`, diagnostic payloads contracted from 1,907 bytes to 74 bytes but cycled through uncovered command identity, semantic mismatch, compound mapping, and uncovered identity again. The terminal artifact recorded eight observed attempts, `runStatus: interrupted`, a failed infrastructure gate, completed cleanup, no surviving scratch roots, and Brotli Q6 progress evidence. A later adversarial review also reproduced a frozen-definition false positive: `Failed commit branch audits all SKUs` plus `Every command commits in item order` discharged the success facet because branch and qualifier regexes matched unrelated text fragments.
- **Approaches tried:**
  - **Attempt:** Deterministically mark every clause not recognized as normative as informational.
    - **Outcome:** Did not work
    - **Why:** English imperatives are open-ended; a heuristic miss cannot prove that user-authored prose is non-normative.
  - **Attempt:** Auto-classify only structurally certain headings and controller-detected unsafe instructions, leaving all ambiguous prose for explicit model classification.
    - **Outcome:** Worked
    - **Why:** It removes mechanical work without converting uncertainty into silent requirement loss.
  - **Attempt:** Split compound identifiers into generic semantic tokens and apply the existing overlap threshold unchanged.
    - **Outcome:** Did not work
    - **Why:** Related identifiers share domain tokens such as `batch`, so the threshold could lose method identity.
  - **Attempt:** Require each mapped atomic requirement to preserve at least one specific compound identifier from its source clause, accepting the exact identifier or its spaced form.
    - **Outcome:** Worked
    - **Why:** It rejects partial-identifier collisions while still allowing a multi-identifier clause to split into atomic requirements.
  - **Attempt:** Emit one repeated-key JSON object per source clause.
    - **Outcome:** Partial
    - **Why:** It removed the duplicate raw source blob but could add metadata overhead. A self-describing column schema plus compact rows retains meaning with a regression proving lower bytes than the prior blob-plus-location payload for a dense 60-clause source.
  - **Attempt:** Count every period as a sentence boundary and measure each atomic mapping against the full coordinated source clause.
    - **Outcome:** Did not work
    - **Why:** Dotted paths became artificial sentences, plural acronyms became false compound identifiers, and a correct atomic command subset could never reach the whole-clause overlap ratio.
  - **Attempt:** Recognize sentence punctuation only at an actual boundary, singularize plural acronyms before identifier splitting, measure overlap against the smaller atomic side, preserve exact backticked command identity, and retain a bounded 96-item capacity.
    - **Outcome:** Worked in focused tests
    - **Why:** It accepts the exact failing task 3 mappings while retaining negative controls for real multi-sentence requirements, wrong same-domain identifiers, and `npm run lint` substituted for the requested commands.
  - **Attempt:** Run the installed compiler and rule gate against the repository's 39,889-byte `AGENTS.md` in a fresh controlled-terminal fixture.
    - **Outcome:** Partial task result, successful architecture smoke
    - **Why:** Compilation produced a 344-byte always-on body and a 1,223-byte injected prompt with no rule links, plus 20 external rule modules and a 4,943-byte catalog. The mutation gate blocked the first write, blocked requirement preparation until one authoritative three-link `read_rules` batch completed, then allowed the exact 29-byte newline-terminated write. The model later violated the smoke prompt by creating an extra verification helper, so the temporary task was interrupted and not counted as a correctness pass.
  - **Attempt:** Improve only the final uncovered-concept diagnostic.
    - **Outcome:** Did not address the root cause
    - **Why:** Atomicity- and relevance-invalid draft requirements were still added to the aggregate used by downstream concept coverage. An invalid repair could therefore make a diagnostic disappear, while deleting it made the same diagnostic reappear.
  - **Attempt:** Count only locally valid mappings and decompose the explicit atomic `either … or …` grammar into stable behavioral facets.
    - **Outcome:** Worked in focused tests
    - **Why:** The model receives the success and failure obligations before its first attempt, maps one high-risk facet per requirement, and cannot use an invalid or compound draft to discharge another obligation.
  - **Attempt:** Validate branch, subject-bound behavior, and universal qualifiers independently across the whole requirement.
    - **Outcome:** Did not work
    - **Why:** A negative branch phrase could contain the substring `commit branch`, while an unrelated sentence supplied `all SKUs`; independent regex truth values did not prove one coherent proposition.
  - **Attempt:** Reject negative polarity before accepting a bare success-branch marker and require all facet elements inside one sentence or criterion proposition.
    - **Outcome:** Worked in focused tests
    - **Why:** It preserves valid source-exact requirements while preventing branch or qualifier evidence from being borrowed across unrelated statements.
- **Root cause:** The first optimization treated heuristic confidence, punctuation, and whole-clause token overlap as semantic authority. The later oscillation had a separate deterministic cause: validation composition was non-monotone because invalid draft requirements counted toward downstream coverage, and noun-only concept coverage lost the subject, predicate, branch, and universal qualifier of a compound atomic clause. The first facet implementation still combined independent whole-requirement regex matches, so lexical evidence could cross proposition and polarity boundaries.
- **Resolution:** Restrict controller classifications to deterministic structure and detected unsafe content; require explicit informational classifications to match structural context markers; retain ambiguous prose; derive referenced prompt indexes from validated clause and facet IDs; preserve source-exact identity and command terms; compare atomic mappings against the smaller semantic side; count only locally valid mappings toward downstream obligations; expose stable behavioral facets for narrowly recognized explicit atomic alternatives; require one facet per high-risk requirement; bind its branch, subject, behavior, and qualifiers within one local proposition; report every missing facet together; emit a compact columnar clause catalog; and allow up to 96 still-bounded atomic requirements for dense specifications.
- **Verification:** The exact regressions failed before their fixes. The final cross-bound regressions first failed because `Failed commit branch` was accepted as success and an unrelated `all SKUs` statement supplied the qualifier; after the repair, the focused facet file passed 11 tests and the broader requirement family passed 39 files and 294 tests. Earlier AGY 3.7 High and independent 5.6 High reviews isolated the dotted-path, acronym, split-clause, invalid-draft composition, and cross-proposition defects. The previous complete non-e2e unit gate passed, including 2,779 coding-agent tests and 292 script tests; it must be rerun for the new candidate. Reinstall previously passed, and the installed 39,889-byte-source smoke proved compiler size and authoritative pre-mutation gating while honestly retaining its later model overreach as a task-correctness failure. A fresh paired task 3 benchmark remains required after this final fix set.
- **Prevention/follow-up:** Keep negative same-domain identifier cases, ambiguous-imperative cases, multi-identifier atomic-split cases, invalid-draft coverage cases, explicit atomic success/failure facet cases, cross-polarity branch phrases, unrelated universal-qualifier propositions, and a dense payload byte bound. Do not call an instruction optimization lossless until both correctness and measured prompt/runtime behavior pass.
- **Reusable learning:** Prompt compaction may automate only classifications proved by structure or controller policy. Downstream coverage must be computed exclusively from locally valid mappings, and high-risk compound semantics need stable behavioral facets whose polarity and qualifiers are bound within one proposition rather than aggregated across a requirement.
