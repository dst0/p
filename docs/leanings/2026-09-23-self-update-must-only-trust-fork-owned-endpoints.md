# 2026-09-23 — Self-update must only trust fork-owned endpoints

- **Status:** Resolved
- **Task/context:** Security review of `p update --self` and the interactive update notice in `packages/coding-agent`. p is a permanent fork of upstream pi.
- **Unexpected observation or failure:** The version check still called upstream pi's `https://pi.dev/api/latest-version` with a `p/<version>` user agent. That endpoint returned upstream metadata (`version` 0.87.1, `packageName` `@earendil-works/pi-coding-agent`). The self-update plan followed any `packageName` that differed from `@dst0/p`: it forced an update and built a two-step command that uninstalled p and installed the named package, for example `npm uninstall -g @dst0/p && npm install -g --ignore-scripts --min-release-age=0 @earendil-works/pi-coding-agent`. A third-party endpoint therefore chose what `p update` installed over p. Rebrand leftovers also pointed the install telemetry ping, `/share` viewer links, OpenRouter attribution, and docs at `p.dev` (NXDOMAIN) and `p.pages.dev` (HTTP 522, not the project's Pages site). The standalone-binary instruction linked `github.com/dst0/p-mono/releases/latest` (HTTP 404).
- **Evidence:** A regression test that serves the upstream rename payload to whatever URL the version check requests recorded `["--prefix", <prefix>, "uninstall", "-g", "@dst0/p"]` then `[..., "install", ..., "@earendil-works/pi-coding-agent"]` on the old code. Live probes: `registry.npmjs.org/@dst0%2fp/latest` returned `@dst0/p` 0.4.41 on the first probe and 5.0.2 later the same session; `api.github.com/repos/dst0/p/releases/tags/v5.0.2` returned the changelog body; `p-agent.pages.dev` serves the project site for every path (SPA fallback, HTTP 200), including `/logo-auto.svg` and `/install.sh`; `POST /api/report-install` returns 405 there.
- **Approaches tried:**
  - **Attempt:** Keep the version endpoint and validate the returned package name.
    - **Outcome:** Did not work
    - **Why:** The endpoint belongs to upstream pi; validating one field still lets a third party decide versions, notes, and request timing.
  - **Attempt:** Use GitHub releases as the version source.
    - **Outcome:** Did not work
    - **Why:** A GitHub release can exist before npm publish, while self-update installs from npm; the check could announce a version `p update` cannot install.
  - **Attempt:** Read `version` from the package's npm registry entry, always reinstall `PACKAGE_NAME`, and fetch GitHub release notes only when the registry version is newer.
    - **Outcome:** Worked
    - **Why:** npm is the only source consistent with what self-update installs, and removing the rename path makes the remote response unable to choose a package.
- **Root cause:** Upstream's rename-following self-update and its `pi.dev` version endpoint survived the fork. Mechanical `pi` to `p` renames produced hostnames (`p.dev`, `p.pages.dev`) the project never owned.
- **Resolution:** `utils/version-check.ts` reads `https://registry.npmjs.org/@dst0%2fp/latest`, accepts only valid semver, sends no p user agent, and fetches `https://api.github.com/repos/dst0/p/releases/tags/v<version>` for notes only when newer; notes are stripped of terminal escape sequences and control characters before rendering. The `updatePackageName`/uninstall-then-install path, `SelfUpdateCommand.steps`, and the two-step command builder were deleted. Telemetry, share links, OpenRouter referer, docs, `SECURITY.md`, and site metadata use `p-agent.pages.dev`; the update notice links the fork's GitHub release for the new version; the binary download link uses `github.com/dst0/p`.
- **Verification:** `test/self-update-release-source.test.ts`, `test/version-check.test.ts`, `test/install-telemetry-ping.test.ts`, `test/fork-owned-network-endpoints.test.ts`, `test/update-notification.test.ts`, and `test/self-update-bun-binary-instruction.test.ts` fail on the old code (43 of 72 tests in the new and updated files, run in a detached worktree at the base commit) and pass with the fix; the old code requested `pi.dev` and ran `npm uninstall -g @dst0/p` followed by `npm install -g ... @earendil-works/pi-coding-agent`. A live smoke against the real registry and GitHub made one registry request when up to date and one extra notes request when older. `npm run check` is clean.
- **Prevention/follow-up:** `test/fork-owned-network-endpoints.test.ts` fails if `pi.dev`, `p.dev`, or `p.pages.dev` (or a subdomain, any letter case) reappears in coding-agent source, published examples, README, or docs. `docs/security.md` states the fork-owned endpoint contract. Open items: `p-agent.pages.dev` does not yet serve `/install.sh`, `/logo-auto.svg`, a `/session/` share viewer, or `/api/report-install`; until it does, the documented installer one-liner and share links do not work, and the telemetry ping lands on the SPA fallback.
- **Reusable learning:** Every host p contacts or tells users to run code from must be one the project controls. Verify ownership with a live probe before adopting a hostname, and never derive hostnames by renaming upstream ones.
- **References:** `packages/coding-agent/src/utils/version-check.ts`, `packages/coding-agent/src/package-manager-cli/list-command.ts`, `packages/coding-agent/src/config/package-roots.ts`, `packages/coding-agent/docs/security.md`.
