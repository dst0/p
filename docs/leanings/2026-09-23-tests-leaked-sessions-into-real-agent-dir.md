# 2026-09-23 — Coding-agent tests leaked session directories into the real `~/.p/agent`

- **Status:** Resolved
- **Task/context:** A developer's real `~/.p/agent/sessions` held about 21.8k session directories (about 971 MB). Their encoded-cwd names matched coding-agent test temp dirs (`pi-runtime-suite-*`, `pi-cache-*`, `pi-runtime-events-*`, `pi-2860-*`, `pi-runtime-cwd-a/b-*`, `pi-runtime-other-*`, `pi-cache-reload-*`, `pi-2753-*`, `p-runtime-coverage-*`). Worked in `packages/coding-agent`.
- **Unexpected observation or failure:** Every test run added more of these directories, some empty and some holding session JSONL. This happened even though the tests created and deleted their own temp cwd and passed `agentDir: tempDir` to the runtime.
- **Evidence:** Running the seven implicated test files with `TMPDIR` set to a unique marker directory added exactly 30 marker-named directories before the fix and 0 after it. After the fix, a 124-file set of harness and agent-dir-related tests also added 0 and left no isolated temp dirs behind. During measurement, an unfixed full-suite run in another checkout added the same 30-directory signature under the default `TMPDIR`. Total directory counts were therefore unusable, and only unique path markers attributed writes correctly.
- **Approaches tried:**
  - **Attempt:** Pass an explicit `sessionDir` in each affected test.
    - **Outcome:** Partial
    - **Why:** It fixes the ten current call sites. Future tests and every other default-path consumer (settings, auth, models, CLI children that inherit the environment) would still resolve the real directory.
  - **Attempt:** Override `HOME` for test runs.
    - **Outcome:** Did not work (rejected before implementation)
    - **Why:** It is far broader than needed. It changes git identity and global config, toolchain caches, and the `homedir()`-based path-formatting expectations for spawned processes and in-process tests.
  - **Attempt:** A Vitest `setupFiles` entry that eagerly `mkdtemp`s a per-file agent dir under `os.tmpdir()` and removes it in `afterAll`.
    - **Outcome:** Partial
    - **Why:** It stopped the home leak but left one empty temp dir per fully skipped file. Vitest does not run file-level hooks when every test in the file is skipped, which `test/agent-session-real-state-update.test.ts` reproduced.
  - **Attempt:** A `globalSetup` that owns one per-run root, with the per-file setup creating its agent dir inside that root.
    - **Outcome:** Worked
    - **Why:** Vitest builds worker environments from `process.env` after global setup runs, so workers inherit the root. The global teardown deletes directories whose `afterAll` never ran, and the per-file setup fails closed if the root variable is missing.
  - **Attempt:** Measure with `TMPDIR` pointing at a long scratch path.
    - **Outcome:** Did not work (misleading)
    - **Why:** Two unrelated tests failed identically with and without the fix: a tsx IPC socket path exceeded the macOS Unix-socket length limit, and an npm-prefix self-update expectation failed. A short marker directory inside the system temp dir avoided both.
- **Root cause:** `SessionManager.create(cwd)` without a `sessionDir` calls `getDefaultSessionDir(cwd)` (`packages/coding-agent/src/core/session-manager/sessionmanager-methods/session-creation.ts:112-115`). That function defaults `agentDir` to the global `getAgentDir()` and eagerly creates the directory (`packages/coding-agent/src/core/session-manager/session-context.ts:124-135`). `getAgentDir()` falls back to `join(homedir(), ".p", "agent")` when `P_CODING_AGENT_DIR` is unset (`packages/coding-agent/src/config/install-paths.ts:169-175`). The runtime's `agentDir` option does not reach a `SessionManager` that the caller constructed. No Vitest setup set `P_CODING_AGENT_DIR`, so the leaks happened at call sites such as `test/suite/agent-session-runtime.test.ts:108,235,504,573`, `test/agent-session-runtime-events.test.ts:88`, `test/suite/regressions/working-state-cache-isolation.test.ts:166,436`, `test/suite/regressions/2860-replaced-session-context.test.ts:104`, `test/suite/regressions/2753-reload-stale-resource-settings.test.ts:80`, and `test/suite/agent-session-runtime-coverage.test.ts:72`. API-key-gated e2e helpers use the same pattern.
- **Resolution:** `packages/coding-agent/vitest.config.ts` now registers `test/vitest-global-setup-agent-dir-root.ts`, which creates and deletes one temp root per run, and `test/vitest-setup-isolated-agent-dir.ts`. For every test file, the per-file setup points `P_CODING_AGENT_DIR` at a fresh directory inside that root, clears `P_CODING_AGENT_SESSION_DIR`, and restores both in `afterAll`. The shared helper lives in `test/isolated-agent-dir.ts`. `test/first-time-setup-fork.test.ts` now clears the agent-dir variable, because a set `P_CODING_AGENT_DIR` also makes `shouldRunFirstTimeSetup` return `false`. Without that change the fork assertion would pass without exercising the fork check.
- **Verification:** Without the setup hooks, `test/agent-dir-test-isolation.test.ts` failed for the right reason: the agent dir resolved to the user directory. The guard checks that the default session dir sits inside the per-run temp root before `SessionManager.create` runs, so any agent dir outside that root fails before a write. That covers the user default, a developer-configured `P_CODING_AGENT_DIR`, and a subdirectory of the real agent dir. An adversarial review then mutated the helper and setup files and ran them with a scratch `HOME`. It found that an earlier, exact-path-only version of the check let two mutants pass and write. The containment check replaced it, and those mutants now fail with nothing written. With the hooks, the guard, the seven implicated files, and the 124-file related set all pass, with zero marker directories added under `~/.p/agent/sessions` and zero leftover isolated dirs.
- **Prevention/follow-up:** `test/agent-dir-test-isolation.test.ts` asserts that the default agent dir sits inside the per-run temp root and outside the user default, and that a default-located session persists only there. It also tests helper and global-teardown lifecycles, including the skipped-file case. `AGENTS.md`, `packages/coding-agent/docs/development.md`, and `packages/coding-agent/test/suite/README.md` document the rule. Remaining items (Open):
  - The existing leaked directories need a one-time cleanup, done separately.
  - `migrateDotPiToDotP()` (`packages/coding-agent/src/migrations.ts:16-50`, called from `runMigrations()` at line 346) uses `homedir()` directly, not the agent dir. Tests still reach it with the real `HOME`: in-process `runMigrations()` in `test/keybindings-migration.test.ts` and `test/config-value-migration.test.ts`, the regression `test/suite/regressions/5661-uppercase-header-values.test.ts`, and CLI and in-process `main()` tests. The adversarial review showed it moving a scratch `$HOME/.pi` entry into `$HOME/.p`. On the reporting machine it is currently a no-op only because every `~/.pi` entry already exists in `~/.p`.
  - Closing that gap needs either a test-run `HOME` override, validated against the full suite (git, npm, and toolchain caches read `HOME`), or a product decision to skip the legacy migration when `P_CODING_AGENT_DIR` is configured.
  - `LearningsStore` also defaults its global file to `homedir()` (`packages/coding-agent/src/core/learnings/learnings-store.ts:15`).
  - `packages/coding-agent/test/utilities.ts:32,117` hard-codes the real `~/.p/agent/auth.json` for opt-in e2e OAuth helpers.
  - `test/suite/agent-session-runtime.test.ts` still leaks two empty temp cwds (`pi-runtime-other-*`, `pi-runtime-cwd-b-*`) into `os.tmpdir()`, but not into home.
  - The TUI debug and crash log paths hard-code `homedir()`, not `getAgentDir()`.
- **Reusable learning:** Neutralize home-directory fallbacks for the whole test runner through environment isolation in setup, not test by test. When cleanup lives in `afterAll`, pair it with a run-level owner, because Vitest skips hooks for fully skipped files. When measuring filesystem leaks on a shared machine, attribute writes by a unique path marker, not by total counts.
