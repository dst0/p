# 2026-08-25 — Successful subprocesses with non-protocol stdout must not be parsed as authority within managed root and UUID child boundaries

- **Status:** Resolved
- **Task/context:** Reinstalling and preparing the macOS Core AI Neural Engine embedding runtime and candidate artifacts for background code indexing.
- **Unexpected observation or failure:** `apple_coreai_artifact.py` exited status 0 and created the immutable candidate artifact directory `qwen3-embedding-0.6b-ane-b1-s64-v1-f226d906-67a2-4ec1-a0c7-4690bbbf5822`, but `buildAppleCoreAiCandidate` rejected the build with `Invalid Core AI candidate build output: invalid JSON` because a third-party dependency (`coreai-torch`) printed a banner notice on stdout before the final JSON payload.
- **Evidence:** `apple_coreai_artifact.py` exited cleanly with code 0 having exported the complete model asset, embedding table, tokenizer, and metadata into the expected destination directory. Child process stdout contained `coreai-torch` banner text followed by the JSON summary, causing `JSON.parse(result.stdout.trim())` to throw a SyntaxError.
- **Approaches tried:**
  - **Attempt:** Filter or suppress third-party banner output inside Python dependencies or redirect dependency stdout in Python.
    - **Outcome:** Did not work
    - **Why:** Dependency print statements (from native extensions, C++ layers, or transitive packages) cannot be controlled reliably from Python without fragile monkey-patching or stream capture that risks masking actual fatal errors.
  - **Attempt:** Use regex or heuristic substring slicing to extract JSON substrings from child process stdout.
    - **Outcome:** Did not work
    - **Why:** Heuristic JSON extraction is brittle when dependencies log JSON-like strings or multi-line warnings, adding parser complexity without adding any security or correctness guarantees.
  - **Attempt:** Treat parent-owned parameters as the authority by locally deriving `{generation, artifactDirectory: path.join(artifactRoot, generation)}` after enforcing managed root (`indexing-service/apple-coreai`) and UUID child boundaries and confirming exit code 0, while relying on the subsequent worker ANE residency probe for correctness.
    - **Outcome:** Worked
    - **Why:** `ensureAppleCoreAiArtifact` generates and validates the unique candidate UUID and target path within managed root boundaries before spawning the builder. Child stdout is not an authority for artifact location or validity; the subsequent one-shot `probeAppleCoreAiWorker` performs the authoritative runtime ANE loadability and compute-unit verification on the candidate directory before atomic promotion.
- **Root cause:** `buildAppleCoreAiCandidate` treated child process stdout as an authoritative structured response channel rather than relying on exit code status 0 and parent-owned path derivation under strict root and generation boundaries. When native or Python dependencies emit uncoordinated banners or diagnostic messages on stdout during initialization, strict stdout JSON parsing fails closed on successful builds.
- **Resolution:** Extracted generation and root boundary validation into `scripts/apple-coreai-generation-path.js` and updated `buildAppleCoreAiCandidate` and `promoteCurrentPointerAtomic` in `scripts/install-apple-coreai.js` to validate absolute canonical managed root boundaries (`indexing-service/apple-coreai` without symlinks across existing ancestry) and canonical UUID child generations before builder spawn and promotion. Checked child process exit status 0 and locally derived `{ generation, artifactDirectory: path.join(artifactRoot, generation) }` without parsing child stdout. Preserved nonzero-exit failure with sanitized bounded diagnostics. The subsequent `probeAppleCoreAiWorker` step remains the sole authority for build correctness and ANE residency before pointer promotion.
- **Verification:** Added regression tests in `scripts/install-apple-coreai.test.js` and filesystem boundary tests in `scripts/apple-coreai-generation-path.test.js` verifying that `buildAppleCoreAiCandidate` succeeds and returns locally derived paths when a builder emits non-JSON banner chatter, fails closed with sanitized diagnostics on nonzero exit codes, rejects relative/broad/wrong-shape/file/symlink roots and traversal generations before builder spawn, and preserves external targets on symlink rejection. Extended `packages/coding-agent/src/core/indexing-version.ts` and `indexing-version-runtime-dependencies.test.ts` to include the helper in version hashing. Ran `node --test scripts/apple-coreai-generation-path.test.js scripts/install-apple-coreai.test.js scripts/install-apple-coreai-artifact-recovery.test.js`, focused vitest tests, and `git diff --check`.
- **Prevention/follow-up:** When parent processes initiate background asset compilation with parent-generated destination parameters, enforce strict managed root and UUID child boundaries up front, treat exit status 0 as the build completion signal, and derive artifact paths locally rather than expecting strict protocol output on child stdout. Rely on dedicated subsequent runtime probes for build correctness authority.
- **Reusable learning:** When a subprocess performs work at a parent-controlled destination, child stdout is subject to uncoordinated third-party dependency chatter and must not be parsed as authority; enforce strict managed root and UUID child boundaries before builder spawn and pointer promotion, verify exit code 0, derive paths locally from parent-owned parameters, and rely on real runtime probes for build correctness.
