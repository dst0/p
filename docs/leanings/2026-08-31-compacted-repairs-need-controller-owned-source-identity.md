# 2026-08-31 — Compacted repairs need controller-owned source identity

- **Status:** Partial
- **Task/context:** Stabilize one-item requirement-definition repair across tool-result compaction, status recovery, follow-up prompts, and session restore.
- **Unexpected observation or failure:** The controller retained a correct rejected draft and frozen source catalog, but each sparse repair response exposed only opaque IDs such as `S3-C2`. Compaction preferred a generic structured context extract over the richer raw result. The model then reconstructed source ordinals from memory, guessed that `S1` was `README.md` and `S2` was `AGENTS.md`, and submitted repairs against the wrong clauses.
- **Evidence:** An installed live AI unit initially rendered Source 1 as the direct user prompt, Source 2 as `README.md`, and Source 3 as `AGENTS.md`. After compaction, the model explicitly guessed a different mapping and needed a later status call to recover the authoritative catalog. The frozen snapshots, stable source IDs, and restored status were unchanged, proving the corruption was in presentation rather than persistence. Adversarial review also showed that list children could expose raw-child facets that differed from the authoritative effective-clause catalog inherited from their introduction.
- **Approaches tried:**
  - **Attempt:** Preserve only the rejected draft revision and tell the model to call status after compaction.
    - **Outcome:** Did not work
    - **Why:** The immediate repair result and its compacted pointer still lacked enough identity to act safely, and session recall surfaced summaries rather than a trustworthy clause join.
  - **Attempt:** Depend on the full status catalog, where source headers and clause rows are rendered separately.
    - **Outcome:** Partial
    - **Why:** Status restores the truth, but its full prompt exceeds the compact context bound and still makes the model join ordinal rows to source headers.
  - **Attempt:** Derive one controller-owned repair envelope from the frozen source snapshots and selected diagnostic for every repair response and compact context extract.
    - **Outcome:** Worked in focused tests
    - **Why:** The actionable item now carries its own target key, exact diagnostic, stable source ID, source ordinal, path/kind/hash, clause location, and exact clause text without copying that data into persisted draft state.
- **Root cause:** Durable repair state preserved target IDs but not the catalog descriptors that give those IDs meaning. `contextExtract` then replaced oversized or detailed tool output with a revision and generic recovery instruction, allowing the model-generated compaction summary to become the only apparent mapping authority.
- **Resolution:** A pure formatter now joins the controller-selected target to authoritative frozen source prompts and clause catalog entries. Immediate rejection, accepted or retained sparse repair feedback, normal and compact status recovery, and requirement-audit/task-verification context extracts reuse the same self-identifying envelope. Facets are derived from the same effective inherited clause used by definition prompts while the envelope retains the raw child location. The protocol explicitly forbids inferring or renumbering unlisted mappings. Unresolvable or unrenderably large targets produce controller-enforced non-actionable status guidance instead of a guessed repair.
- **Verification:** The regression first reproduced a compacted pointer containing only the revision and generic guard. It now proves that initial rejection, the next adopted one-item repair, compaction, status, and restore retain the same stable source ID and exact clause descriptors while advancing only the selected clause. Pure formatter cases cover referenced requirement targets, direct-prompt targets, effective list-child facets, unresolved identities, and oversized non-actionable targets. The complete requirement-verification family passes 118 files and 1,047 tests. Reinstall and installed live closure remain pending.
- **Prevention/follow-up:** Never ask a model to join opaque controller IDs from remembered or summarized catalog structure. Keep the persisted source snapshots authoritative, derive a bounded one-item envelope at render time, and use retrieval-only guidance when the exact target cannot fit safely.
- **Reusable learning:** Stable IDs are not self-identifying; every compacted actionable repair must carry the authoritative descriptor that makes its target unambiguous.
