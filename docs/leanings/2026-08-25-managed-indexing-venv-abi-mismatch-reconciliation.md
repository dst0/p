# 2026-08-25 — Managed indexing venv ABI mismatch reconciliation

- **Status:** Resolved
- **Task/context:** Managing and verifying Python virtual environments for the background code indexing daemon across interpreter upgrades and reinstall flows.
- **Unexpected observation or failure:** `indexing-service/venv` contained an ABI-mixed environment where `pyvenv.cfg` declared Python 3.12.13 and was originally created by `python3.12`, but `venv/bin/python` and `venv/bin/python3` symlinked to `python3.14` and executed Python 3.14.6, while `coreai-venv` correctly executed Python 3.12.13. `scripts/indexing-python-environment.js` reused the venv solely when its requirements marker matched the selected source interpreter hash, permitting an ABI-mixed venv to be reused across mismatched Python runtimes.
- **Evidence:** Live inspection revealed `indexing-service/venv/pyvenv.cfg` specifying Python 3.12.13 while `indexing-service/venv/bin/python` executed Python 3.14.6. This ABI issue was independent and non-causal to the CoreAI MPSGraph cache load failure.
- **Approaches tried:**
  - **Attempt:** Relink only `bin/python` and `bin/python3` to the selected Python interpreter.
    - **Outcome:** Did not work
    - **Why:** Relinking symlinks leaves existing compiled binary wheels (C extensions, PyTorch, numpy) targeting the previous Python ABI in `site-packages`, resulting in dynamic linker errors or runtime crashes.
  - **Attempt:** Rely strictly on requirement marker comparison without inspecting the venv interpreter's ABI.
    - **Outcome:** Did not work
    - **Why:** Requirements markers only hash the source interpreter and requirement specifications; if the venv directory was previously created by or modified under a different Python version, the marker check can pass or fail to clean obsolete binary wheels.
  - **Attempt:** Delete the entire service directory or agent root on mismatch.
    - **Outcome:** Did not work
    - **Why:** Destructive deletion wipes out database data (Qdrant), daemon state, logs, and independently healthy environments like `coreai-venv`.
  - **Attempt:** Probe selected and venv Python `major.minor` ABI versions via an isolated helper before marker checking or venv creation, fail closed without deletion if the selected interpreter probe fails, delete only the exact `options.venvDirectory` on missing/broken venv interpreter or `major.minor` mismatch, and allow the existing install flow to recreate it cleanly.
    - **Outcome:** Worked
    - **Why:** Detects and self-heals the confirmed interpreter major.minor mismatch without touching sibling files, databases, or separate runtimes on install and reinstall flows, while matching ABI does not prove wheel or pyvenv.cfg integrity and atomic staged venv switching is a possible future alternative.
- **Root cause:** Virtual environment reuse logic checked requirement file content and source interpreter versions but did not verify that the existing `venv/bin/python` matched the selected interpreter's `major.minor` ABI, allowing an existing directory with mismatched symlinks or wheels to persist across installer invocations.
- **Resolution:** Implemented `getPythonMajorMinor` and `reconcilePythonVenv` in `scripts/indexing-python-environment.js`. Before checking requirements markers or running `python -m venv`, the installer probes the selected Python interpreter (failing closed without deletion if probing fails). If `options.venvDirectory` exists, it probes the venv interpreter; if missing, unexecutable, or having a `major.minor` mismatch, only `options.venvDirectory` is removed (`fs.rmSync(options.venvDirectory, { recursive: true, force: true })`), enabling the standard install flow to rebuild a fresh, clean venv. Matching `major.minor` versions (ignoring patch version differences) are preserved. Added `indexing-python-environment.js` to `computeIndexingVersion` in `packages/coding-agent/src/core/indexing-version.ts`.
- **Verification:** Ran `node --test scripts/indexing-python-environment.test.js` verifying probe failure closed-state, missing binary cleanup, broken interpreter cleanup, `major.minor` mismatch cleanup, patch-version preservation, non-existent venv safety, and sibling sentinel isolation. Ran `vitest` on `packages/coding-agent/test/indexing-version-runtime-dependencies.test.ts` proving `indexing-python-environment.js` inclusion in `computeIndexingVersion`.
- **Prevention/follow-up:** Always validate that target execution environments match the required ABI before attempting marker evaluation or incremental installation; enforce fail-closed probing of candidate interpreters; restrict cleanups strictly to the managed resource directory.
- **Reusable learning:** Managed Python virtual environments must explicitly reconcile `major.minor` runtime ABIs against selected interpreters before reuse; this detects and self-heals the confirmed interpreter major.minor mismatch, while matching ABI does not prove wheel or pyvenv.cfg integrity and atomic staged venv switching is a possible future alternative.
- **References:** `scripts/indexing-python-environment.js`, `scripts/indexing-python-environment.test.js`, `packages/coding-agent/src/core/indexing-version.ts`, `packages/coding-agent/test/indexing-version-runtime-dependencies.test.ts`.
