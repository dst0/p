# 2026-10-31 — code-index tests leaked a late Qdrant version-check warning into Vitest teardown

- **Status:** Partial
- **Task/context:** CI intermittently failed the "Test with coverage" step although every test passed. Vitest reported `Vitest caught 1 unhandled error ... EnvironmentTeardownError: [vitest-worker]: Closing rpc while "onUserConsoleLog" was pending. This error originated in "test/cli.test.ts"` for `packages/code-index` (reported on CI run 41161067881; its log was not retrievable when this was investigated). Work was done in `packages/code-index/test/cli.test.ts` and the package Vitest config.
- **Unexpected observation or failure:** The initial hypothesis was that the `cli main` tests mock `process.exit` as a no-op, so `main()` keeps running past the "exit" and logs after the test ended. The no-op mock does let code run on (a probe showed `indexRepo` being called with the non-existent repo path after the mocked `exit(1)`), but that code only calls mocked, awaited methods and cannot produce a write after teardown.
- **Evidence:** A temporary copy of `cli.test.ts` wrapped `console.log/warn/error` before any spy was installed, so only writes that bypass the spies were recorded. Every run recorded exactly 7 unmocked `console.warn("Failed to obtain server version. Unable to check client-server compatibility...")` calls, one per `main()` test, all with the stack `@qdrant/js-client-rest/dist/esm/qdrant-client.js` promise `catch` handler. Each landed a few milliseconds after the test that constructed the client had finished and its console spies had been restored; the last one arrived about 1 ms before the file's `afterAll`, which leaves no margin on a loaded runner. After the fix the same probe recorded 0 unmocked writes over 5 runs.
- **Approaches tried:**
  - **Attempt:** Reproduce the CI error by running `test/cli.test.ts` repeatedly: plain (30 runs), `--sequence.shuffle` (15), `--coverage` (15), under 14 busy-loop processes (40), and against a local TCP listener that reset connections after a random delay (40).
    - **Outcome:** Did not work
    - **Why:** 0 unhandled errors in about 140 runs. The teardown race needs the write to be in flight exactly when the worker closes its RPC channel, a window of roughly a millisecond.
  - **Attempt:** Make the `process.exit` mock throw a sentinel error so the code under test stops like a real exit.
    - **Outcome:** Worked (hygiene), but did not address the leaked write
    - **Why:** It closes a real gap, because the previous tests asserted behavior after a point where the process would have ended, but the late `console.warn` comes from the unawaited Qdrant client constructor, not from code after the exit.
  - **Attempt:** Disable the raw client's `checkCompatibility` for every test through a package-wide Vitest `setupFiles` module that wraps `QdrantClient`.
    - **Outcome:** Worked
    - **Why:** The constructor no longer issues the fire-and-forget request, so no write can arrive after a test ends. Production code keeps the library default.
- **Root cause:** `new QdrantClient(...)` from `@qdrant/js-client-rest` fires an unawaited `GET /` version check from its constructor and reports failure with `console.warn` when it settles. Tests that construct `CodeIndexer`/`QdrantClient` without a Qdrant server therefore produce a console write after the constructing test finished and its console spies were restored, occasionally during worker teardown. The original CI failure was not reproduced locally, so the link between this mechanism and that specific CI run is inferred from the matching error text and the measured margin.
- **Resolution:** `packages/code-index/test/setup-qdrant-client-without-version-check.ts` (registered in `packages/code-index/vitest.config.ts`) disables the version check for all tests in the package. `cli.test.ts` now mocks `process.exit` with a throwing `ExitCalled` sentinel, asserts that the not-found path stops before touching the indexer, and removes the process listeners `main()` registers. `qdrant-client-construction-network.test.ts` fails if constructing a client ever issues a request or console write again.
- **Verification:** The regression test fails without the setup file (global `fetch` is called on construction) and passes with it. `cli.test.ts` passed 32 consecutive runs, 16 shuffled runs and 8 coverage runs; the full `packages/code-index` suite passed 3 times (55 files, 445 tests) and once with coverage, with no unhandled errors.
- **Prevention/follow-up:** Watch CI for a recurrence; if the error returns, the leak is elsewhere and this entry should be superseded. Separately, production code still creates the raw client with the library default, so a missing or incompatible Qdrant prints the same warning from the CLI and from consumers of `QdrantClient`; whether that should be silenced or surfaced properly is a product decision outside this change. `cli-and-indexer-more.test.ts` still mocks `process.exit` as a no-op, which is acceptable only because it also mocks `process.on` and invokes the cleanup handlers directly.
- **Reusable learning:** An unawaited promise started inside a constructor can write to the console after the test that created the object has finished; mocking the console per test does not contain it. Remove the side effect (or await it) instead of widening the spies, and make any mocked `process.exit` throw so the code under test cannot run past a real exit.
- **References:** `packages/code-index/test/cli.test.ts`, `packages/code-index/test/qdrant-client-construction-network.test.ts`, `packages/code-index/test/setup-qdrant-client-without-version-check.ts`, `packages/code-index/vitest.config.ts`.
